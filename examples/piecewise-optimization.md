# 分段线性函数优化分配案例

> 纯数学问题：将总量分配给多个变量，使分段线性目标函数最小化，同时满足排名约束。
> 本案例已脱敏，不含任何业务领域信息。

### 项目背景

**问题类型**：分段线性函数优化 / 资源分配

**核心问题**：给定一个总量 `Total`，分配给 `N` 个变量 `v_1, ..., v_N`，使目标函数 `Σ T(v_i)` 最小。其中 `T(x)` 是分段线性函数，每段有不同的斜率（税率）和常数项（扣除项）。

**约束**：
- 总量约束：`Σ v_i = Total`
- 排名约束：`v_1 > v_2 > max(v_3, ..., v_N)`（前两名严格递减，且第二名大于其余任一）
- 区间约束：每个变量落入的区间决定了它的斜率和常数项

**难度来源**：
1. 分段函数在区间边界处不连续（有跳跃）
2. 排名约束与区间边界相互作用，微调易触发跨越
3. 搜索空间大（区间数^变量数 种组合）

---

### 设计过程

#### 1. 数学建模

**目标函数**：

```
min  Σ T(v_i) = Σ (r_i × v_i − d_i)
s.t. Σ v_i = Total
     v_1 > v_2 > max(v_3, ..., v_N)
     v_i 落在选定区间内
```

其中 `T(x)` 分段线性：每个区间 `k` 内 `T(x) = r_k × x − d_k`。

**关键洞察**：
- 固定区间组合后，`Σ d_i` 为常数 → 最小化 `Σ(r_i × v_i)`
- 低税率区间应取上限，最高税率区间取剩余
- 同税率区间内边际税率相等，内部分配不影响总值

#### 2. 求解策略

**两阶段分离**：

```
阶段1：枚举所有区间组合（区间数^变量数 种）
       → 对每种组合算理论最优总值，排序
阶段2：对排名最优的组合，构造满足排名约束的具体分配
       → 若构造失败，顺序回退到下一个组合
```

**枚举优化**：
- 利用"同区间边际相等"，只枚举区间组合，不枚举区间内取值
- 搜索空间从 `O(区间数^变量数 × 取值数)` 降到 `O(区间数^变量数)`
- 去重：相同区间组合（不分变量顺序）只保留一个

#### 3. 构造分配

**核心难点**：同区间内变量必须严格递减（满足排名），但微调可能跨越临界点。

**单向微调策略**：

```python
# 伪代码
def build_allocation(bracket_totals, groups, ranking):
    # 1. 按税率从高到低分配排名（高税率 → 高排名）
    # 2. 同区间内均分，余数给排名高的
    # 3. 确保同区间内严格递减：
    #    - 只从低排名变量"减"（不跨下界）
    #    - 绝不给高排名变量"加"（不跨上界）
    #    - 省下的额度全部给"最高税率区间、容量最大"的变量
    pass
```

**为什么单向**：给高排名变量"加"会把它推向区间上界，一旦越过临界点，目标函数跳跃式增加。而"减"只可能触底（下界），下界是开区间，触底也只是退到下一区间，影响可控。

#### 4. 验证

**多角度交叉验证**：

| 验证项 | 方法 | 发现的问题 |
|--------|------|-----------|
| 总量 | `Σ v_i == Total` | 构造过程中额度丢失 |
| 排名 | 逐对比较 | 微调方向错误 |
| 区间归属 | `lower < v_i ≤ upper` | 临界点跨越 |
| 单点公式 | 手动展开一个变量 | 常数项倍乘 |
| 理论 vs 实际 | 枚举值 == 求和值 | 构造 bug（核心） |
| 守恒 | 分配前后总量相等 | 中间过程丢值 |
| 基准对比 | 与朴素方案对比 | 优化方向错误 |

**最关键**：理论枚举值 == 实际求和值。若不等，构造逻辑必有 bug。

---

### 关键决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 求解方法 | 枚举 + 构造两阶段 | 变量数少，枚举可行；分离降低复杂度 |
| 搜索空间压缩 | 只枚举区间组合 | 利用边际相等性，避免全枚举 |
| 微调方向 | 单向（只减不加） | 从根本避免跨越上界 |
| 验证方式 | 多角度交叉 | 单一验算共享盲点 |
| 容纳方 | 最高税率区间变量 | 容量最大，吸收额度不跨界 |

### 踩过的坑

**问题 1：常数项倍乘误用**

- **症状**：总值偏离预期，临界点跳跃异常
- **原因**：误把常数项 `d` 乘以区间跨度倍数 `k`，写成 `d × k`
- **解决方案**：用区间端点反推常数项，确认只减一次
- **详细文档**：[math-optimization-reasoning.md](../pitfalls/math-optimization-reasoning.md)

**问题 2：临界点跨越**

- **症状**：理论最优值与实际构造值不一致，差出一截
- **原因**：微调时给高排名变量"加"，推过区间上界，触发跳跃
- **解决方案**：单向微调，只减不加，省下额度给容量最大的变量
- **详细文档**：[math-optimization-reasoning.md](../pitfalls/math-optimization-reasoning.md)

**问题 3：枚举与构造脱节（重复推理）**

- **症状**：反复在枚举和构造间来回，同一组合验证多遍
- **原因**：枚举假设区间内连续，构造却有排名约束，两者假设不一致
- **解决方案**：两阶段分离，保留排序结果，构造失败顺序回退
- **详细文档**：[math-optimization-reasoning.md](../pitfalls/math-optimization-reasoning.md)

### 经验总结

**做得好的地方**：
1. 用数学模型抽象问题，识别出"固定区间组合后 Σd 为常数"的关键简化
2. 枚举前先压缩搜索空间（利用边际相等），避免暴力全枚举
3. 最终用 7 项交叉验证全部通过

**可以改进的地方**：
1. 常数项倍乘错误本应在"临界点验证"阶段第一时间发现，却拖到后期
2. 构造逻辑第一版直接"加给高排名"，未考虑边界，导致返工
3. 枚举与构造的假设不一致，应在枚举阶段就纳入可构造性检查

**给其他项目的建议**：
1. 分段函数问题，先验证常数项是否倍乘（用端点反推）
2. 含排名/边界约束的分配，微调永远"只减不加"
3. 理论最优值必须与实际构造值交叉验证，不等即有 bug
4. 枚举与构造分两阶段，但保留排序结果以便顺序回退
