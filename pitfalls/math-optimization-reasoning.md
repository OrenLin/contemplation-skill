# 数学优化推理踩坑记录

> 适用于：分段线性函数优化、资源分配问题、含排名/区间约束的最小化问题。
> 本文档抽象为纯数学问题，不含任何业务敏感信息。

---

## 问题 1：常数项倍乘误用（公式上下文错配）

### 症状

- 计算出的总值与预期严重偏离
- 在区间临界点处，函数值不连续且跳跃幅度异常
- 验算时发现"同区间内不同取值，扣除项却被放大"

### 根本原因

分段函数形如 `T(x) = r × x − d`，其中 `d` 是该区间的常数项（扣除项）。

常见错误：把另一个上下文的公式搬过来时，误以为 `d` 需要乘以某个系数（如区间跨度对应的倍数），写成 `T(x) = r × x − d × k`。

1. 公式来自不同计税/计费口径（综合口径 vs 单独口径），常数项的处理规则不同
2. 未核对原始公式定义，凭"看起来要对齐量纲"的直觉加了倍数
3. 缺少临界点验证，错误被掩盖到验算阶段才暴露

### 解决方案

**方案 A：用区间端点反推常数项**

在任一区间内，取两个已知点 `(x1, T(x1))`、`(x2, T(x2))`，解方程：

```
T(x1) = r × x1 − D
T(x2) = r × x2 − D
→ D = r × x1 − T(x1)
```

若反推出的 `D` 与文档给的 `d` 一致 → 常数项只减一次；若反推出 `D = d × k` → 说明倍乘了。

**方案 B：临界点连续性检验**

分段函数在区间内部应保持线性。取区间上限 `x = upper`：

```
正确：T(upper) = r × upper − d        # 只减一次
错误：T(upper) = r × upper − d × k    # 倍乘后值偏小
```

对比官方/权威口径在 `upper` 处的值，立刻能发现倍乘错误。

**推荐方案**：方案 B，临界点是天然的"放大镜"——倍乘错误在端点处偏差最大，一眼可见。

### 验证清单

- [ ] 常数项 `d` 是否只减一次（非 `d × k`）
- [ ] 区间上限处计算值与权威口径一致
- [ ] 区间内任取两点，斜率等于 `r`（线性验证）
- [ ] 跨区间时函数值发生预期内的跳跃（而非平滑过渡）

## 问题 2：分段函数临界点跨越陷阱

### 症状

- 枚举求得的理论最优值，与实际构造分配后算出的总值**不一致**
- 实际总值比理论值大出一截
- 某个变量本应落在区间 A，却被微调推入了区间 B

### 根本原因

分段线性函数在区间边界处是**不连续**的（有跳跃）。设区间 A 上限为 `U`，区间 B 下限为 `U+1`：

```
T(U)     = r_A × U − d_A
T(U+1)   = r_B × (U+1) − d_B
跳跃量   = T(U+1) − T(U)  （通常为正且较大）
```

在构造满足排名约束的分配时，为了让"高排名变量 > 低排名变量"，常见做法是给高排名变量加 1。若该变量恰在区间上限附近，`+1` 会把它推过临界点，触发一次大跳跃，导致总成本激增。

1. 微调逻辑只考虑了排名约束，没考虑区间边界
2. 理论模型假设变量可连续取值，实际构造却受离散排名约束
3. "加给高排名"的方向恰好是跨越上界的危险方向

### 解决方案

**方案 A：单向微调——只减不加**

```
原则：
- 排名微调时，只从低排名变量"减"（绝不跨越下界）
- 绝不给高排名变量"加"（避免跨越上界）
- 省下的额度全部归给"容量最大的最高税率区间"的那个变量
```

理由：最高税率区间上限最大、剩余容量最多，吸收额外额度也不会跨越边界。

**方案 B：构造前先做边界安全检查**

```
对每个变量 v_i：
  剩余到上界的余量 = upper_i − v_i
  若余量 < 微调幅度 → 标记为"不可加"
  剩余到下界的余量 = v_i − lower_i
  若余量 < 微调幅度 → 标记为"不可减"
```

只允许在"安全"的方向上微调。

**推荐方案**：方案 A。它从根本上避免了"加"这个危险动作，不需要逐个检查，逻辑更简单、更不容易出错。

### 验证清单

- [ ] 每个变量实际落在其预期区间内（`lower < v ≤ upper`）
- [ ] 微调后没有任何变量跨越临界点
- [ ] 实际总值 == 理论枚举最优值（差异为 0）
- [ ] 排名约束严格满足（`v_高排名 > v_低排名`）

## 问题 3：枚举最优与构造可行脱节（重复推理浪费）

### 症状

- 枚举了所有区间组合，找到理论最优
- 但构造具体分配时反复失败、反复返工
- 同一个"理论最优"被验证了好几遍，每次都因构造问题推翻

### 根本原因

枚举阶段优化的目标是"区间组合"（哪些变量进哪个区间），假设区间内可连续分配。

但实际构造还要满足额外约束（如排名），这些约束会与区间边界相互作用：

1. 枚举认为"同区间内分配不影响总值"——但这只在无排名约束时成立
2. 一旦加入排名约束，同区间内必须严格递减，微调可能触发临界点跨越
3. 理论最优的区间组合，可能无法构造出满足排名且不跨界的分配

结果：枚举得到的"最优"在构造阶段不成立，于是反复回到枚举、反复构造，形成重复推理循环。

### 解决方案

**方案 A：枚举阶段就纳入"可构造性"约束**

在评估每个区间组合时，不只算理论税额，还要检查：

```
能否构造出满足以下全部条件的分配？
  1. 总额约束 Σ v_i = Total
  2. 每个变量落在其指定区间
  3. 排名约束 v_1 > v_2 > max(v_3, v_4, ...)
  4. 不跨越任何临界点
```

不可构造的组合直接判为不可行，避免后续返工。

**方案 B：分离"求最优组合"与"构造分配"两阶段，但用快速预筛**

```
阶段1：枚举求理论最优组合（快速）
阶段2：尝试构造，若失败 → 取枚举排名下一个组合，而非回到阶段1重算
```

关键：保留枚举的排序结果，构造失败时顺序回退，不重复枚举。

**推荐方案**：方案 B。阶段分离更清晰，且保留排序结果可顺序回退，避免重复枚举的全量开销。同时构造逻辑用"单向微调"（见问题 2）大幅降低失败率。

### 验证清单

- [ ] 枚举结果已排序并保留，构造失败可顺序回退
- [ ] 每个被采纳的组合都验证过"可构造性"
- [ ] 没有对同一组合重复枚举
- [ ] 构造逻辑与枚举逻辑的假设一致（区间内是否连续）

## 问题 4：同区间边际税率相等的简化洞察

### 症状

- 对同区间的多个变量反复尝试不同分配，试图找"更优"
- 实际上同区间内任意分配，总值不变，做了无用功

### 根本原因

在 `T(x) = r × x − d` 的分段模型中：

```
同区间内多个变量 v_1, v_2, ..., v_n（同属区间 k，税率 r_k，扣除 d_k）：
Σ T(v_i) = r_k × Σv_i − n × d_k
```

`Σv_i` 在区间组合确定后基本固定（受总额约束），`n × d_k` 也固定。

→ **同区间内的分配方式不影响总值**，边际税率处处相等。

未识别这一点，会在同区间内反复搜索"更优分配"，纯属浪费时间。

### 解决方案

**识别并利用边际税率相等性**

```
1. 同区间内的变量 → 任意分配总值相同，只需满足排名约束即可
2. 跨区间才是优化重点 → 低税率区间取上限，高税率区间取剩余
3. 排名约束尽量在"同区间内"用微调解决，避免跨区间挪动
```

**推论**：枚举时只需枚举"区间组合"（哪些变量进哪个区间），无需枚举区间内的具体取值。这把搜索空间从 `O(区间数^变量数 × 取值数)` 降到 `O(区间数^变量数)`。

### 验证清单

- [ ] 同区间内不同分配，总值差异为 0
- [ ] 枚举只针对区间组合，未对区间内取值做全枚举
- [ ] 排名约束优先在同区间内解决

## 问题 5：结果验证方法论

### 症状

- 算出一个结果，但不确定对不对
- 反复用同一种方式验算，无法发现系统性错误（如倍乘错误）

### 根本原因

单一验算方式会与计算过程共享同一盲点。例如用同一个公式验算同一个公式，倍乘错误无法被发现。

### 解决方案

**多角度交叉验证清单**

```
1. 总量验证：Σ v_i == Total ?
2. 约束验证：排名、区间归属是否满足 ?
3. 单点验证：任取一个变量，手动展开公式逐步计算 ?
4. 交叉验证：逐项求和的总值 == 理论枚举最优值 ?
   → 若不等，构造逻辑有 bug（最常见：临界点跨越）
5. 守恒验证：分配前总量 == 分配后总量（中间过程无丢失）?
6. 区间验证：每个 v_i 是否真的落在其声明的区间内 ?
7. 对比验证：与一个"朴素基准方案"对比，确认有优化 ?
```

**关键原则**：第 4 项是发现构造 bug 的核心。理论枚举值是"应有"的值，实际求和值是"实际得到"的值，两者不等说明构造过程引入了偏差（通常是临界点跨越）。

### 验证清单

- [ ] 至少 3 种独立方式验算（不共享同一公式路径）
- [ ] 理论值与实际值交叉对比
- [ ] 守恒律（总量不变）已验证
- [ ] 与基准方案对比确认优化方向正确

---

## 总结：避免推理浪费的 5 条原则

| 原则 | 说明 |
|------|------|
| 先验公式常数 | 用区间端点反推常数项，确认是否倍乘 |
| 单向微调 | 只减不加，避免跨越上界 |
| 两阶段分离 | 枚举求组合 + 构造求分配，失败顺序回退 |
| 利用边际相等 | 同区间内不搜索，只优化跨区间组合 |
| 多角度交叉验证 | 理论值 vs 实际值是发现 bug 的核心 |
